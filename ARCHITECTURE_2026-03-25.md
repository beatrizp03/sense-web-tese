## System Architecture

### Components
- **Sense Desktop (Electron app)**
  - Handles device connection (serial/Bluetooth), chunked data storage, and IPC with the renderer.
  - Uses `ChunkedDataWriter` to write acquisition data to disk in chunked JSON files.
  - Manages session folders and chunk file naming based on acquisition start time.
- **Sense Web V2 (Next.js/React app)**
  - Provides the user interface for live data acquisition, device control, and visualization.
  - Publishes frames via `framePublisher` for UI and storage.
  - Manages session/segment metadata in localStorage and coordinates with Electron for chunked storage.

### Data Flow
1. **Acquisition Start**
   - User connects to a device and starts acquisition from the web UI.
   - Electron creates a new session folder and initializes `ChunkedDataWriter`.
2. **Frame Handling**
   - Frames are published to the UI for visualization and queued for storage.
   - When a buffer threshold is reached, frames are flushed to Electron for chunked disk write.
3. **Chunked Storage**
   - Electron writes frames to chunk files (e.g., `sample1_chunk0.json`).
   - Each chunk file contains a JSON array of frames.
   - No empty chunk files are created; files are only created when there is data to write.
4. **Pause/Resume/Stop**
   - On pause/resume, a new segment is started, and segment metadata is updated.
   - On stop, all remaining frames are flushed, and the session is finalized.

## Key Changes Made (2026-03-25)

### 1. **Robust Chunk File Creation**
- **Problem:** Empty chunk files were being created after pause/resume or stop, even when no data was present.
- **Solution:**
  - Refactored `ChunkedDataWriter` so that after a chunk is finalized, a new chunk file is only created when there is data to write (on the next write). This prevents empty chunk files and matches the original behavior from the legacy implementation.
  - In `writeChunk`, if the stream is null (after finalize), a new chunk file is created only when frames are present.

### 2. **Session/Segment Management**
- **Clarified** the split between session metadata (localStorage) and chunked frame storage (Electron/disk).
- **Ensured** that segment and sample metadata are always updated and stored consistently across pause, resume, and stop events.

### 3. **Code Hygiene and Debugging**
- **Reviewed** connection/disconnection logic to ensure ports are always closed and re-opened correctly.
- **Added** guards to prevent chunk writes when there is no data, both in the renderer and main process.
- **Validated** that the CSV export and summary page reconstruction match the chunked data, with no data loss.
